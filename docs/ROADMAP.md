# Roadmap

This file is the plan of collections. The Status page of the site reads it, and the tracker of the project mirrors it.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| C1 | The first package | done | `@mark1russell7/collections` is on npm at 0.3.0: lists, deques, maps, trees, heaps and graphs of dependencies, with no runtime dependencies. |
| C3 | defaultHash on plain objects (0.3.1) | blocked | The client session owns this draft until it lands. It waits for a heavy runner slot, then for the two hash bench runs. The figures go in #14. The role takes the repo when it merges. |
| C2 | One meaning of deep equality | blocked | `deepEqual` in `testing/check.ts` and `deepEq` in `utils/defaults.ts` have near-identical names and different meanings. Remove one name. Lists, hash sets and hash maps also default to `===`, so they do not find NaN, and a native `Set` does. This item decides the default equality of each structure. It waits for C3 because C3 changes the same file. |
| C4 | Audit of Funk | done | Funk has no middleware. Of its 415 lines of library, 2 ideas are new for collections, and `Either` has no home in the family. Funk is public on GitHub with the MIT license, so the word private in the strategy is out of date. |
| C5 | Design of one middleware core | done | Both systems run the same fold: 4 copies in client, 1 here. Client agreed to import one file. It moves last, and its bundle budget decides. |
| C6 | Ship the middleware core | done | Version 0.4.0 is on npm with the entry `./layers`: typed chains of 100 layers, a result that keeps each capability, 4 laws and the capability law. The bench of PR #19 ran 5 jobs on 4 CPU models. A call through a built stack has no cost (bound 1.003). A build costs 14 % more at 3 layers and 5 % more at 10 and 30 layers. |
| C7 | Client imports the core | blocked | Client moves its fold to `@mark1russell7/collections/layers` at `^0.4.0`, and its PR gives the bundle size before and after. `LruMap` goes when C18 ships. `bundle`, its `compose`, the async guard and context tracking stay in client. |
| C8 | A home for Option and Result | done | Version 0.7.0 is on npm since 2026-11-07. It deletes the `_tag` copy in `core/effects.ts`. The safe middleware gives the `Optional` and `Result` of `@mark1russell7/optional` 1.2.0, which has no dependencies. A new map law found that `hashMap.get` threw for a key with the value `undefined`. The fix is in the same version. |
| C9 | Finish the move from client | open | `@procedures/collections` and `@procedures/dag` already re-export this package. Their range `^0.1.0` cannot reach 0.3.0, so they do not get the `defaultHash` fix. Overlay, storage and undo stay in client, and each needs a decision. The client session owns the change. |
| C10 | Laws for every structure | in progress | Model-based property tests on `fast-check` for each list, set, map and queue, and for stacks of behaviors. A CI baseline of coverage and mutation score comes first, so the gain can be measured. The coverage baseline of `main` is 66.99% of statements and 63.83% of branches. The tests of the bounded, LRU and TTL layers and of stacks of layers found six faults, which 0.8.0 corrects. The first full mutation run gives the baseline, with no gate: `maps` 63.40%, `sequences` 71.79%, `behaviors` 63.26%, `core` 20.00%, `fx` 47.78%, `extras` 82.93%. Each part reads all its tests. The low score of `core` is next. |
| C11 | Benches of each structure | open | Time and memory of each structure against native types and the common libraries, through `@mark1russell7/rigor-bench` in CI. A speed gate follows after 5 runs give its limit. |
| C12 | Review of the public API | done (0.10.0) | The review in `docs/API-REVIEW.md` gives a verdict for each of the 363 names: 246 keep, 23 change, 72 remove and 22 move. The strategist named the homes of the emitter and the channels (S1, S2). Item C26 moves the channels to `@mark1russell7/service`. A test fails when a new export has no verdict. Mark decided D1 to D6. Version 0.10.0 applies them through the branch `next`. The mean collectors and `average` fold with the running summary of `@mark1russell7/rigor-statistics` 0.1.25, the home of `SummaryStatistics`. |
| C13 | Guides for each entry | done (0.10.0) | Two PRs merged on 2026-11-07. The first PR has three guides in `docs/guides`: lists, maps and sets, and queues. A test runs each example of the guides and of the README with `markdownExamples` of `@mark1russell7/rigor-testkit`. The examples found that `subList` gives a copy, not the view that its doc told. The second PR has the guides of the DAG and the graph. Its examples found that `failFast` runs each node of the failed level, also the nodes that did not start. The third PR has the guide of the layers: `compose`, its types, its four laws, and behaviors on a collection. It found that the doc of `Chain` told the wrong place of the error: the compiler marks the first argument, not the bad pair. Later PRs have the guides of the behaviors, the iterables, the rank keys, the summary tree, the async queues, and the events and caches. The guide of the events and caches found that the layers guide told of no event for an eviction, but C23 added that event. The guide of equality, hashes and order found the two defects of C38. The guide of the factories found the three defects of C40. The guide to write a layer found the two defects of C41. The names of `utils/helpers.ts` get no guide, because version 0.10.0 removes them (C12, decision D3). A later PR gives examples to the last 14 values with no guide: five collectors, the four `synchronized` aliases, `bundle`, `visualizeDAG`, `height` and `StorageListeners`. Its examples found no defect. That PR named 14 values, but 14 more had no guide: the seven classes of the factories, `flatMap`, `flatten`, `skip`, `skipWhile`, `takeWhile`, `distinctConsecutive` and `tap`. A later PR gives them examples, and a test of `docs.test.ts` fails on a value that no guide names. On `next` the list of exceptions is empty. The guide of `bounded` shows the five functions, the six policies, the removal channel and `onOverflow`. Its reading found the defects of C42. The checks of `./testing` are a copy of the checks of client. They move to `@mark1russell7/rigor-testkit`, and a later MINOR version removes `./testing`, after client moves. |
| C14 | Reference from the doc comments | open | A generated reference on the site, with each public export documented. It follows the API review, so it does not document exports that go. |
| C15 | A site with live demos | done | The page `/structures/` of PR #27 has an explorer of each of the 10 structures of the real library, with the cost of each operation. The render gate of `site-pages` checks it at 1280 and 390 wide, light and dark. |
| C16 | Bench results on the site | open | CI rebuilds charts of the bench records on each merge, with the release and date of the data. |
| C17 | Two small ideas from Funk | open | An operation that accepts exactly one element and refuses other counts, and an intern table that gives one canonical object for equal values, on `defaultHash`. |
| C18 | LRU capacity check and deleteWhere | done | Client asked for 2 changes so that it can remove `LruMap`. The LRU and bounded layers throw `RangeError` for a capacity that is not a positive whole number, and `LRUCache` gets `deleteWhere`, which is not a use. PR #24 is merged, and 0.5.0 is on npm. |
| C19 | executeDAG skips the dependents of a failed node | done | With `failFast: false`, `executeDAG` started a node whose dependency failed. PR #25 skips such a node, and the option `skipDependents: false` keeps the old behavior. Version 0.6.0 is on npm. Client has a copy of the executor with the same flaw. |
| C20 | LRU and TTL layers: keys with the equality of the base | done | `lruMap`, `ttlMap` and `ttlCollection` find each key with the equality of their base: a `Map` for the default `keyEq`, a `treeMap` for a comparator, and a `hashMap` with `eq` and `hash` for the others. `HashMap` gives its hash as `hash`, as `linkedHashMap` and `hashSet` do. PR #34 merged into the branch `next`, and version 0.11.0 has it. C10 found it. |
| C21 | boundedList: one drop end for a front insert | done (0.10.0) | On a full `drop-oldest` `boundedList`, `insert(0, x)` drops the last element, as `unshift(x)` does. Each other index drops the first element. An insert at a bad index no longer drops an element. 0.10.0. C10 found it. |
| C22 | Move runModel to rigor, with clearEachRun | in progress | `runModel` moves to `@mark1russell7/rigor-testkit/model` (rigor#108, 0.1.1), with `dispose`, `parameters` and a `clear` for the spies of vex. The plugin `fc.beforeEach` of `fast-check` 4.10 replaces `clearEachRun`. After the release, collections imports `runModel` from rigor and deletes its copy. |
| C23 | A layer tells the layers above it about a removal | done | The bounded layers, `lruMap` and `ttlMap` send their removals on a removal channel, and each layer above them gets them. An evented layer then works at each place in a stack. The tests of the channel found six more faults, which 0.9.0 (PR #31) corrects. C10 found the need. |
| C24 | The evented layers emit an event for each bulk change | done (0.9.8) | Each element of `addAll`, `insertAll`, `removeAll`, `retainAll` and `removeRange` gives its own event. The composite methods of `eventedMap` use its `set` and `delete`. The replay laws hold the bulk steps. The package has no `removeIf`. C23 found it. |
| C25 | The contract checks move to `rigor-testkit` | in progress | The six checks of `./testing` copy the checks of client, and test helpers have their home in rigor. A comparison with `node:assert` found that only `rejects` adds something. rigor#114 adds `rejects` to `rigor-testkit`. Client then imports it, and a MINOR version of collections removes `./testing`. |
| C26 | The channels move to service | done (0.10.0) | The channels, `select`, `ticker`, `timeout` and `workerPool` are tools of concurrency, so their home is `@mark1russell7/service/channel`. Service 0.6.6 has them. Version 0.9.1 marks the 13 names `@deprecated`, and a test holds each tag. Version 0.10.0 removes them. |
| C27 | A readonly view blocks each change | done (0.7.1) | A readonly view of `arrayDeque`, `priorityQueue` or `linkedList` removed an element through `pollOrUndefined`, and private methods were callable at run time. PR #46 blocks each of them. A test puts each method of the 10 structures in the reads or the blocked names. |
| C28 | `reentrantSynchronized` is not reentrant | done (0.10.0) | The examples of the behaviors guide found it. Each use makes a new `Symbol`, so the check for the holder of the lock does not match. A nested use waits for the outer lock, and the two uses do not end. PR #70 removes it on the branch `next`, and version 0.10.0 releases the removal. |
| C29 | The generic `safe()` does nothing | done (0.10.0) | The examples of the guide of the behaviors found it. `safe()` gives the collection with no change and adds no property `safe`. `safeList`, `safeQueue`, `safeDeque` and `safeMap` work. Version 0.10.0 removes `safe()`. It changes nothing, so no caller depends on its result. The guide sends each caller to the safe layer of its shape. |
| C30 | `take` reads no value after the last one | done (0.7.2) | `take(source, n)` asked its source for one more value before it stopped. PR #48 stops after the last value, and reads nothing when `n` is 0. A test counts the reads of the source. |
| C31 | Set operations keep the hash and the comparator | done | The s20 audit found four faults. `HashSet` copies dropped a custom hash, and `intersection` of a generator gave an empty set. `TreeSet` set operations compared with `===`, not with the comparator. A readonly view of an `lruCache` let `deleteWhere` empty it. Version 0.9.2 corrects each one, with a test that fails before the fix. |
| C32 | `readWriteLock` lets `for of` and the iterators work | done | The s20 audit found that `readWriteLock` made each method async, also `Symbol.iterator`. So `for of` over the view threw, and `keys`, `values` and `entries` released the lock before the iteration. In 0.9.7, a method with a symbol key stays synchronous, so `for of` works. `keys`, `values`, `entries` and `descendingIterator` give a promise of a copy, read under the lock. |
| C33 | `boundedQueue` on a deque bounds `addLast` and `offerLast` | done (0.10.0) | `boundedQueue` with capacity 2 over an `arrayDeque` took 3 elements through `addLast`. C42 corrects it: the bounded layer bounds each add method of the base. Its test tries `addLast` and `offerLast` of `ArrayDeque` under `boundedQueue` at each policy. |
| C34 | Doc comments start with their subject, and a lint rule holds it | done | 98 doc lines started with a verb and no subject, for example "Retrieves and removes the head". Each of the 98 lines has a subject (#55). The root config turns on the rule `doc-subject` of ste-lint 0.2.0 as an error. Thus CI fails on a new doc comment that starts with a verb in the imperative. |
| C35 | The summary tree as plain functions, and a weight gate for each entry | done | A bundle keeps each method of a class, so the rope of typeset kept all of `SummaryTree`. The entry `./summary-tree` gives the tree as plain functions over a plain record, and the class wraps them. The rope import weighs 1842 gzip bytes, against 2551 for the class. `bundle-weight.test.ts` holds a limit for each entry, and an unused import of each entry adds no byte. Version 0.9.3 is on npm, and the rope of typeset uses it (typeset#59). |
| C36 | `AsyncQueue`: a check of the capacity, and one text for each error | done | The examples of the async guide found two defects. With a capacity of -1, `remainingCapacity` was -1. With `NaN`, each `put` waited with no end. Also a new put gave `Queue is closed`, but a waiting put gave `Queue closed`. The fix makes `asyncQueue` throw a `RangeError` for a capacity that is not a whole number of 0 or more, or `Infinity`. Each error has one text (0.9.5). |
| C37 | LRU and TTL: the same rules in the layers and the classes | in progress | The reading for the guide of the events and caches found three differences. The fix: `has` is not a use of `lruMap`, as with `LRUCache`. `ttlMap`, `ttlCollection`, `TTLCache` and `ttlCache` refuse a `ttl` or `checkInterval` that is not greater than 0. `touch` of `TTLCache` gives an expired entry to `onExpire`, as `get` does. The PR targets the branch `next`, and version 0.11.0 has it. |
| C38 | Comparators: a number for each pair, and the opposite sign for a swap | done | The reading for the guide of equality, hashes and order found two defects. `numberCompare` gave `NaN` for two equal infinities. `dateCompare` and `defaultCompare` gave `NaN` for two invalid dates. Then a `treeMap` held the key two times, `has` gave false, and `get` threw. Also `defaultCompare(null, undefined)` and `defaultCompare(undefined, null)` both gave -1. In 0.9.6, each comparator gives 0 for these pairs, and `null` comes before `undefined`. A law test with `fast-check` examines the sign, the swap and transitivity of each comparator. |
| C39 | `defaultCompare` across types: a transitive order | done (0.10.0) | The law test of C38 found that `defaultCompare` compares the text of two values of different types. This order is not transitive: `9 < 10 < "10z" < 9`. It also gives 0 for `1` and `"1"`, and for two different objects. The fix orders by type first, then by value. It changes the order of a sort of mixed types, so it is a breaking change. PR #71 puts the fix and a law of transitivity on the branch `next`. Version 0.10.0 releases them. |
| C40 | `range` and `nCopies`: exact steps and a check of the count | done (0.10.0) | The reading for the guide of the factories found three defects. `range` adds `step` at each step, so `range(0, 1, 0.1)` gives 11 numbers. `range(0, Infinity)` and `nCopies(Infinity, value)` do not stop. `nCopies(2.5, value)` gives 3 copies, and `nCopies(NaN, value)` gives an empty list. A fix computes `start + i * step` and refuses a count that is not a finite integer. The fix changes results, so version 0.10.0 has it. Property tests examine the steps for a drift of floats, and the error for a bad count or end. |
| C41 | `hasCapability` sees the members of a proxy, and `eventedMap` orders its events | done (0.10.0) | The reading for the guide to write a layer found two defects. `hasCapability` used `in`, and the layer proxies had no `has` trap, so it gave `false` for `on`. A layer below `eventedMap` that removed the key of the same `set` gave `delete` before `set`, so a replay kept the key. Version 0.10.0 corrects both: each layer proxy that adds a member has a `has` trap, and `eventedMap` gives `set` before a removal of its own key. A changed result is a breaking change, so the fix goes to the branch `next`. |
| C42 | The bounded layers bound each add method of the base | done (0.10.0) | The reading for the guide of `bounded` found 23 add methods that went past the capacity, for example `push` of a deque under `boundedQueue`. One shared layer with one table of the add methods and their drop ends replaces the three layers. A test tries each add method of each layer and base at each policy. The fix stacks on #33 and ships in 0.10.0. |
| C43 | A search of the strongly connected components | done (0.9.11) | coeval asked for it (tenet 2): its core has its own search. The entry `./graph` gets `stronglyConnectedComponents` and `strongComponentsCompact`, by the algorithm of Tarjan with their own stack. Version 0.9.11 releases them. coeval uses `strongComponentsCompact`, with the same digest over 600 seeded graphs. |
| C44 | `SummaryMonoid` becomes the shared `Monoid` | blocked | `@mark1russell7/structures` ships on 2026-11-21 as the one home of `Monoid` and its law checks (tenet 2). `SummaryMonoid` then becomes a type alias of the shared `Monoid`, so the old name does not break. The shared law checks test the monoids of the users of `./summary-tree`. The target date is 2026-11-28. |
| C45 | The clock dependency moves to `@mark1russell7/automata` | blocked | The state-machine package `@mark1russell7/algebra` gets the new name `@mark1russell7/automata` at 0.9.0, with the same API. The clock options of `bounded`, `lru` and `ttl` name its type `Clock`. Thus the move is MINOR, in 0.11.0. It follows the release of `automata` 0.9.0, planned for 2026-11-21. |
